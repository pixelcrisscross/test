# Speaker run-of-show (90 minutes)

| Time | Speaker action |

## Speaker script prompts

### Opening

"Imagine five people editing the same project. How do we know who changed what? What if a change breaks something? How do we go back? Version control gives us a history and a safe way to collaborate."

### Repository and codebase

"A codebase is the source code that implements a program. A repository is the project space that stores files and their Git history. A repository can hold code, documentation, tests, images, and configuration—not only source code."

### README and Markdown

"When you discover an unfamiliar repository, README is usually the first thing you should read. Markdown lets us create readable documentation using plain text: headings, lists, links, tables, and code blocks."

### Git and GitHub

"Git is the version-control tool. GitHub is a platform where Git repositories can be hosted and where people collaborate through pull requests, issues, Actions, and more."

### Pull request

"A commit records a snapshot. A pull request proposes that those changes be incorporated into another branch. A review lets someone inspect the exact diff before it is merged."

### Automation

"Notice that nobody manually sends you the next lesson. A repository event triggers a GitHub Actions workflow, the workflow checks what happened, and it posts the next instruction. This is a simple example of automation used in real development teams."

## Live demo checklist

- Keep the template repository page open.
- Keep a test learner repository and its Actions tab open.
- Open the exercise issue in a separate tab.
- Demonstrate a branch, a Markdown file, a commit, a PR, a check, and a merge.
- Have at least two helpers ready for login, account verification, Git installation, and workflow errors.
